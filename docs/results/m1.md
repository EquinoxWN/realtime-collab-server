## Local load run (`make load`)

One Node.js process runs the server and every client, so the clients compete with the server for
the same event loop; these numbers show how cost grows, not what a deployed server can do (that is
the M3 k6 proof). Each client makes its edits at random positions with 0 to 10 ms pauses; latency
is measured from the sender's clock to each other client applying the edit.

| Clients x edits | Edits applied | Deliveries | Converged | Delivery latency p50 / p95 / p99 | Time to converge |
|---|---|---|---|---|---|
| 10 x 50 | 500 | 4,500 | yes | 2.5 / 5.0 / 6.2 ms | 726 ms |
| 50 x 20 | 1,000 | 49,000 | yes | 27.2 / 41.0 / 49.7 ms | 900 ms |
| 200 x 20 | 4,000 | 796,000 | yes | 576 / 915 / 1,075 ms | 14,288 ms |

Every run ended with all replicas equal to the server's text. Deliveries grow with the square of
the room size (each edit goes to every other member), and every client in this process also
applies every edit to its own replica, so the 200-client run does 200 times the CRDT work of a real
deployment where each client is a separate browser. This is the motivation for M2's fan-out across
nodes and for measuring real sockets in M3.
